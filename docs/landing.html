Activity monitor · AI spend cockpit · macOS

You already know what Claude Code cost. Flightdeck shows what it became.

A usage meter stops at the invoice. Flightdeck reads your Claude Code transcripts and the git history of the repo they touched, so it can tell you how much of what the agent wrote is still in HEAD — and what each surviving file actually cost.

It is also a full system monitor: CPU and memory straight from the Mach kernel, every listening port, what is draining the battery, and where the disk went. One app for the machine and the bill.

The part that took the longest

Nothing in this app is a plausible-looking guess.

Monitoring tools quietly invent numbers: a burn rate extrapolated from two samples, a context gauge pinned to a window size it assumed. Flightdeck marks anything it cannot attribute exactly, and deletes what it cannot measure honestly at all.

≤

At most this much. A windowed spend whose baseline snapshot predates the window — the true figure is somewhere below the mark, and the app says so rather than rounding into a claim.

≥

At least this much. A total that includes a model with no published price. Real cost is higher by an unknown amount, so the number is shown as a floor.

5d old

Measured, but not now. Plan-limit percentages come from Claude Code's own cache, refreshed only while a session runs. A five-day-old reading describes last week — it gets a badge, and it never triggers an alert.

Removed

Burn rate, and three others. They could not be computed from what is on disk without inventing the inputs, so they are gone instead of decorative.

Five decks · ⌘1 – ⌘5

The machine and the bill, in one window.

⌘1 · Cockpit

Everything at a glance

  • Live vitals and today's spend on one screen
  • Alerts before a plan limit, budget or context ceiling bites
  • Command palette on ⌘K

⌘2 · Claude Code

Sessions, insights, MCP

  • Waste report — sessions that cost money and changed no code, billed tool calls that failed
  • Churn hotspots — files the agent keeps rewriting, usually a missing CLAUDE.md rule
  • Session forensics — full turns, tool timeline, per-model tokens, one-click resume
  • Plan limits with reset countdowns

⌘3 · System

Kernel-level, not estimated

  • Mach HOST_CPU_LOAD_INFO across P and E cores
  • Real memory — active, wired, compressed
  • Process control with a POSIX kill fallback for unbundled CLI tools
  • Open ports and what is listening on them

⌘4 · Storage

Where the disk went

  • Disk radar — largest files, by type, by subtree
  • Duplicate hunter with content hashing
  • Deep uninstaller that finds the leftovers too
  • Build cruft — reclaimable dev caches

⌘5 · Spend

Budget guardrails

  • Daily budget with a live bar and a notification before you cross it
  • Per-project and per-model breakdowns
  • Exact fractional cost — no rounding into a wrong total

Privacy

Everything stays on this Mac.

No account, no telemetry, no network calls of its own. Flightdeck reads local files and runs git in your repositories. It writes exactly one file, and backs it up first.

read ~/.claude/projects/**/*.jsonl
read ~/.claude.json
read git history of repos a session touched
write ~/.claude/settings.json ← backed up first

The optional statusline and hooks are what let Flightdeck see live context and tool activity. Connecting them is a single confirmed write to settings.json, shown to you beforehand, taken with a backup and an optimistic-concurrency check so a hand edit is never clobbered. Decline it and the app still works from transcripts alone.
